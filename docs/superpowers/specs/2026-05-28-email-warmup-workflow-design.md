# Email Warm-Up Workflow — Design Spec

**Date:** 2026-05-28
**Owner:** Gracie Barra Whittier / GHL admin
**Status:** Approved — ready for implementation

## Goal

Build sending reputation for the newly-added GHL sending domain so it can reliably deliver ~50–200 transactional emails/day (booking confirmations, trial reminders, welcome emails) to the inbox — not Promotions or Spam — within 3 weeks.

## Approach

A single GHL workflow drips 5 short, engagement-optimized emails to the studio's most-engaged contacts. Daily volume is ramped manually by tagging N contacts each morning. Replies, opens, and clicks generated by the drip teach inbox providers (Gmail, Outlook, Yahoo) that the new domain is a trusted sender.

## Prerequisites

Before this workflow runs, the new domain must be fully authenticated:

- SPF, DKIM, DMARC, and tracking CNAME all showing green in **GHL Settings → Email Services → Dedicated Domain**
- DMARC policy set to `p=none` (monitor mode) initially
- "From" address on the new domain configured for Alex (Program Director) in his GHL staff profile
- Test send to a personal Gmail address → "Show original" shows `SPF: PASS`, `DKIM: PASS`, `DMARC: PASS`, all aligned to the new domain

If any of the above is not green, fix DNS first. Warm-up cannot compensate for broken auth.

## Components

### 1. Smart List — "Engaged Contacts (Warmup Pool)"

Filter criteria:

- Opened any email in the last 60 days
- Has a valid email address (not bounced)
- Not tagged `unsubscribed` or `do-not-email`
- Sort: most recent open first (so we start with hottest contacts)

Expected pool size: 500–2,000 contacts (depending on studio's recent activity).

### 2. Trigger Tag — `warmup-2026-06`

A static tag manually applied each morning to a slice of the smart list. Workflow entry trigger = "Tag added: `warmup-2026-06`".

### 3. Workflow — "Domain Warm-Up — June 2026"

Step-by-step:

| Step | Action | Wait |
|------|--------|------|
| 1 | Send Email 1 (welcome / hello) | — |
| 2 | Wait 3 days | — |
| 3 | Send Email 2 (reply-bait question) | — |
| 4 | Wait 4 days | — |
| 5 | Send Email 3 (value tip) | — |
| 6 | Wait 7 days | — |
| 7 | Send Email 4 (soft invitation) | — |
| 8 | Wait 7 days | — |
| 9 | Send Email 5 (engagement check) | — |
| 10 | Remove tag `warmup-2026-06` | — |
| 11 | Add tag `warmup-complete-2026-06` | — |

Total duration per contact: 21 days.

### 4. Daily Ramp Schedule (manual tagging)

Each weekday morning, the admin opens the "Engaged Contacts (Warmup Pool)" smart list, sorts by most recent open, and bulk-applies the `warmup-2026-06` tag to the top N contacts who don't already have it. Skip weekends.

| Week | Weekday Tag Count | Resulting Daily Send Volume (by end of week) |
|------|-------------------|----------------------------------------------|
| 1 (Days 1–5)  | **15/day** | ~15–30/day |
| 2 (Days 6–10) | **30/day** | ~60–90/day |
| 3 (Days 11–15)| **50/day** | ~150–200/day |

After Week 3, the domain is warmed. Stop tagging new contacts; let the existing cohort finish their 21-day drip. The transactional workflows that need this domain can now run at target volume.

- Reply-friendly From address (not `noreply@`)

## Success Criteria

Warm-up is considered successful when, measured at the end of Week 3:

| Metric | Target |
|--------|--------|
| Open rate (across the drip) | ≥ 25% |
| Bounce rate | < 2% |
| Spam complaint rate | < 0.1% |
| Reply rate (Emails 2, 4, 5 combined) | ≥ 3% |
| Gmail "Show original" inspection of a sent message | SPF/DKIM/DMARC all `PASS` aligned to new domain |
| Mail-tester.com score on a fresh send | ≥ 9/10 |

If bounce rate exceeds 2% during any week, **pause tagging immediately** and clean the list before resuming.

## Monitoring

Admin checks GHL Email Stats daily during warm-up:

- **Settings → Email Services → Statistics** — view per-day send volume, open rate, bounce rate, spam complaints
- If complaint rate spikes above 0.1% on any day → pause workflow, investigate which segment is complaining
- Track DMARC reports sent to `dmarc@yourdomain.com` weekly to spot any unauthorized senders or auth failures

## Post-Warm-Up

After the final cohort completes Day 21:

1. Tighten DMARC: change policy from `p=none` to `p=quarantine`
2. Archive the warm-up workflow (don't delete — keep for reference)
3. Future re-warm-up months can clone this workflow with a new tag (`warmup-2026-09`, etc.) if the domain goes idle for 60+ days

## Out of Scope

- Automating the daily tagging (manual is intentional — keeps admin in control of volume and ramp speed)
- Sender reputation monitoring tools (Google Postmaster Tools setup is recommended separately)
- Migrating existing transactional workflows to the new sender domain — that happens after warm-up completes
